# Quadrotor Model

Shared by every stage: `core/quadrotor_model.py`. One dynamics builder produces all model
variants (nominal, disturbance-parameterized, augmented, with motor dynamics), so every stage
uses exactly the same physics.

## States, inputs, conventions

| Property | Value |
|----------|-------|
| Rigid-body state $x$ (13) | $`[p_x\; p_y\; p_z,\; v_x\; v_y\; v_z,\; q_w\; q_x\; q_y\; q_z,\; p\; q\; r]`$ |
| Rotor thrusts $f$ (4) | $`[f_1\; f_2\; f_3\; f_4]`$ [N], the thrust the rotors produce |
| Input $u$ (4) | thrust commands $`f_{\text{cmd}} = [f_{\text{cmd},1} \dots f_{\text{cmd},4}]`$ [N] to the ESCs ([motor dynamics](#motor-dynamics)) |
| Frames | position and linear velocity in the world frame; angular rates $`p\; q\; r`$ in the body frame |
| Attitude | unit quaternion, scalar-first, body → world, `+` motor layout |
| Hover | $q = [1, 0, 0, 0]$, $f_{\text{hover}} = mg/4 \approx 2.45$ N |
| Input bounds | $`f_{\min} \le f_{\text{cmd},i} \le f_{\max} = 3 f_{\text{hover}} \approx 7.36`$ N, $f_{\min} \approx 0.074$ N (idle) |
| Integration | ERK4 (acados) |

> Naming: $q$ in $`[p\; q\; r]`$ is the body pitch rate, not to be confused with the quaternion
> components $q_w, q_x, q_y, q_z$. $\Omega$ is a rotor speed, $\omega = [p, q, r]$ the body rate.

The rigid-body equations below take the rotor thrusts $f$ as given. Where $f$ comes from, the
motor dynamics, is described [after them](#motor-dynamics). Stages not yet migrated to the
motor dynamics still use $f$ directly as the input, with $0 \le f_i \le f_{\max}$; the
13-state version of all stages is tag `rigid-body`.

## Equations of motion

**Translational dynamics** (world frame). Thrust acts along the body $z$-axis, so only the third
column of the rotation matrix $R(q)$ is needed:

```math
\dot{p} = v, \qquad
\dot{v} = \frac{f_{\text{total}}}{m}\, R(q)_{:,2} - g\, e_z, \qquad
f_{\text{total}} = f_1 + f_2 + f_3 + f_4 .
```

**Rotational kinematics** (quaternion, scalar-first):

```math
\begin{aligned}
\dot{q}_w &= \tfrac12\,(-q_x p - q_y q - q_z r)
\\ \dot{q}_x &= \tfrac12\,(q_w p + q_y r - q_z q)
\\ \dot{q}_y &= \tfrac12\,(q_w q - q_x r + q_z p)
\\ \dot{q}_z &= \tfrac12\,(q_w r + q_x q - q_y p)
\end{aligned}
```

equivalently $`\dot{q} = \tfrac12\, q \otimes [0, p, q, r]`$.

**Rotational dynamics** (rigid-body Euler equations, body frame, independent of the attitude
representation):

```math
I \dot{\omega} = \tau - \omega \times (I \omega), \qquad \omega = [p, q, r],
```

with the torques generated by differential thrust

```math
\tau_x = L(f_4 - f_2), \qquad \tau_y = L(f_3 - f_1), \qquad \tau_z = c_\tau(-f_1 + f_2 - f_3 + f_4).
```

$L$ is the arm length, $c_\tau$ the rotor drag-to-thrust coefficient and $I$ the diagonal inertia
tensor. Stacking the above gives the 13-state rigid-body model $\dot{x} = f_{\text{rb}}(x, f)$.

## Motor dynamics

On a real drone the flight controller does not set the thrust. It sends a thrust **command** to
each ESC (electronic speed controller), which runs a speed loop on its motor; the thrust follows
from the rotor speed. The chain, per rotor $i$:

```math
f_{\text{cmd},i}
\;\xrightarrow{\text{inverse thrust map}}\;
\omega_{\text{cmd},i} = \sqrt{\bar f_{\text{cmd},i} / k_f}
\;\xrightarrow{\text{ESC speed loop}}\;
\Omega_i
\;\xrightarrow{\text{thrust}}\;
f_i = k_f\, \Omega_i^2 ,
```

with $`\bar f_{\text{cmd},i} = \mathrm{clip}(f_{\text{cmd},i},\, f_{\min},\, f_{\max})`$ (the ESC
envelope). The reactive yaw torque of a rotor is $k_q \Omega_i^2 = c_\tau f_i$, so the torque
equations above hold unchanged.

**Plant** (`create_rotor_plant`) — the rotor speeds are states, the closed speed loop is a
first-order lag:

```math
\dot\Omega_i = \frac{\omega_{\text{cmd},i} - \Omega_i}{\tau_m},
\qquad
\text{state } [x;\, \Omega] \in \mathbb{R}^{17}.
```

**MPC prediction model** (`create_thrust_lag_model`, `create_thrust_lag_disturbance_model`) — the
thrusts are states, with the lag written directly in thrust:

```math
\dot f_i = \frac{f_{\text{cmd},i} - f_i}{\tau_m},
\qquad
\text{state } [x;\, f] \in \mathbb{R}^{17},
\quad \text{input } f_{\text{cmd}} .
```

The two agree to first order: differentiating $f = k_f \Omega^2$ gives

```math
\dot f = 2 k_f \Omega\, \dot\Omega = \frac{f_{\text{cmd}} - f}{\tau_m} \cdot \frac{2\Omega}{\omega_{\text{cmd}} + \Omega},
```

and the last factor is $1$ for small steps. For large steps the plant spins up slower
($\omega_{\text{cmd}} > \Omega$, factor $< 1$) and spins down faster than the MPC model: a small,
realistic plant–model mismatch. `core/motor_check.py` measures it (time to 63 % of a step:
30 ms small step, 35 ms to full throttle, 18 ms to idle) and checks the hover equilibrium and
the linearization.

The rotor speeds are measured (ESC rpm telemetry) and passed to the MPC as $f = k_f \Omega^2$
(`rotor_to_thrust_state`). The input bounds sit on the command; the thrust states need none,
since the lag keeps $f$ between its start value and the command.

**Linearization at hover** (`get_thrust_lag_hover_linearization`) — the old input matrix now
couples the thrust states into the body; the command reaches the body only through the lag:

```math
A = \begin{bmatrix} A_{\text{rb}} & B_{\text{rb}} \\ 0 & -\tfrac{1}{\tau_m} I_4 \end{bmatrix},
\qquad
B = \begin{bmatrix} 0 \\ \tfrac{1}{\tau_m} I_4 \end{bmatrix},
```

with $(A_{\text{rb}}, B_{\text{rb}})$ the 13-state hover linearization (`get_hover_linearization`).

| Parameter | Value |
|---|---|
| $\tau_m$ (`TAU_MOTOR`) | 30 ms, closed speed-loop time constant |
| $\Omega_{\min}$, $\Omega_{\text{hover}}$, $\Omega_{\max}$ | 130, 751, 1300 rad/s (idle, hover, full throttle) |
| $k_f$ (`K_F`) | $f_{\max} / \Omega_{\max}^2 = 4.35 \cdot 10^{-6}$ N·s² (full throttle gives exactly $f_{\max}$) |
| $k_q$ (`K_Q`) | $c_\tau k_f$ |
| $f_{\min}$ (`F_MIN`) | $k_f \Omega_{\min}^2 \approx 0.074$ N = $f_{\max}/100$ |

Since $\tau_m$ is shorter than the MPC sample time ($T_s = 50$ ms), the OCPs integrate with two
RK4 steps per shooting interval; one step would leave $0.27$ of a thrust step after one sample
instead of the exact $e^{-T_s/\tau_m} = 0.19$.

## Disturbance model (Stages 3–4)

A constant disturbance $`d = [d_f;\, d_\tau] \in \mathbb{R}^6`$ enters as a world-frame force and a
body-frame torque:

```math
\dot{v} = \frac{f_{\text{total}}}{m}\, R(q)_{:,2} - g\, e_z + \frac{d_f}{m}, \qquad
I \dot{\omega} = \tau - \omega \times (I\omega) + d_\tau .
```

| Variant | Role of $d$ | Used by |
|---|---|---|
| nominal | $d = 0$ | Stages 1–2 (Stage 1: thrust-lag model) |
| disturbance-parameterized | runtime parameter `model.p` | MPC ($p = \hat d$) and plant ($p = d_{\text{true}}$) |
| augmented | extra states, $\dot d = 0$, $`z = [x;\, d] \in \mathbb{R}^{19}`$ | EKF and MHE |

## Quaternion details

- **Cost weights.** For small angles $\phi \approx 2 q_x$, $\theta \approx 2 q_y$, $\psi \approx 2 q_z$, so quaternion
  weights are set about $4\times$ the equivalent Euler-angle weights. $q_w$ is only lightly weighted,
  since it is not independent of the vector part.
- **Norm drift.** The plant state passes through `quat_normalize(x)` after every step,
  which also enforces the $q_w > 0$ hemisphere.
- **Linearization.** At hover, $q_w$ is an uncontrollable marginal mode of the linearized model,
  so Riccati-based computations (CARE, DARE) use the 12-state model without $q_w$ and re-insert
  it afterwards with its weight from $Q$.
